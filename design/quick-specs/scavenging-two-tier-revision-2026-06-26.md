## 0. 为什么改（一句话）

调研同类作品（致命公司 / This War of Mine / Moonlighter / Edith Finch）结论：**物品的情感不来自"读它的内容"，来自 类别私密性 + 客户用途反差 + 视觉痕迹**。原 spec 把"信件/照片/公文"等纸片和"家电/工具"等物件**一视同仁地塞进 12 个平行类目**，导致两个问题：

1. 纸片读不到内容、长得又像，撒满全图 → 沦为无意义的"捡纸"，浪费"地球遗物"主题；
2. 纸片**看不出价值**，扛不起"重量 vs 价值"的现场取舍 —— 而那是搜刮玩法的核心爽点。

**修订核心**：把可捡拾物拆成**两层**，承担不同玩法功能；客户偏好机制随之从"偏好具体类目"改为"偏好层一大类 + 层二情感点缀"。

## 1. 双层架构

| | 层一 · 搜刮经济主体（Salvage） | 层二 · 情感 / 语境锚点（Relic） |
|---|---|---|
| **玩法功能** | 扛"重量 vs 价值"现场取舍 | 承载主题情感 |
| **物品** | 视觉化"物件"：器物 / 家电 / 工具 / 衣物 / 医药 / 宗教器物 / 酒 / 标本 / 家具 | 私人遗物：信 / 照片 / 儿童画 / 日记 / 公文 |
| **价值可读性** | 看模型大致判断值不值这个重量 | 看不出价值，靠语境 |
| **数量 / 分布** | 高频，撒量（每图 10–14 件，原 `itemsPerMapInstance`） | 少而精，每图手工 3–6 件，对应"谁的命运" |
| **客户偏好** | 偏好作用于**大类**（见 §2），favoured ×1.3 | 不走大类；对**匹配客户类型**触发情感加价（见 §3） |
| **呈现** | 剪影 + 结算揭晓价值 | 视觉私密性 + 检视看痕迹 + 结算客户用途反差 |
| **复用** | 高，做变体 | 低，独特手工 |

> **两层都不破坏原 spec 的"无指定目标物（D-G）"原则**：层二遗物不是"必须找到否则失败"的目标，是"找到了有特殊情感时刻 + 可能加价"的点缀。

## 2. 层一大类（Material Class）— 取代"12 类目偏好"

原 Rule 5：客户偏好 1–2 个 **category**（12 选 1–2）。
**改为**：客户偏好 1–2 个 **Material Class（大类）**。大类数量压到 **4 个**，便于委托文本暗示、便于玩家记忆，每个对应一种"火星客户想消费的地球侧面"。

**【推荐方案 — 待 PM 确认，见 §8 决策点 D1】**

| 大类 | 涵盖的层一物件 | 火星客户的消费动机 |
|---|---|---|
| **家居烟火 Domestic** | 器物 / 摆件、家电、衣物随身、住宅家具、医药（家庭药箱） | "真实地球人怎么过日子"——最普遍的怀旧（移民一代 / 二代主力） |
| **劳作器械 Labour** | 专业工具 / 器械 | "真实的地球劳动"——机构 / 猎奇收藏 |
| **自然遗存 Natural** | 本土植物标本（含污染样本） | "真实的（被污染的）地球生态"——雪莲那类高价危险委托 |
| **文化信仰 Culture** | 宗教礼仪器物、文化出版物（书 / 唱片）、酒 / 奢侈消费品 | "真实的地球精神 / 享乐生活"——三代收藏者 / 会所图 |

- 客户偏好的大类，其下所有层一物件结算 `× materialClassPreferenceMultiplier`（沿用 1.3）；其余物件与 Free Salvage = 市场价。
- 委托文本**暗示大类、不点名**（原 Rule 2 不变）：例如"客户偏好居家陈设甚于工业器材"。
- 分布不均是**有意的**：Domestic 最常见（主流搜刮），Labour/Natural/Culture 是特定客户的高价偏好——读懂委托、专挑偏好大类，是"打得好"的体现。

## 3. 层二情感机制（Relic）

层二遗物（信 / 照片 / 儿童画 / 日记 / 公文）**不走大类偏好**，走"情感匹配"：

- **基础价值低**（轻、且火星客户买的不是"物"是"情感真实性"）。
- **对匹配的个人客户**（移民一代 / 二代怀旧型，见 `world-background-2098.md` 客户分代）：触发 `× relicEmotionalMultiplier`（**高方差，建议 1.5–3.0**）+ **特殊结算文本**。例：一代客户收到同年代的家书 → 加价 + 一段动人又不安的反馈。
- **对机构 / 三代收藏客户**：层二遗物被**冷淡处理**——市场价或略低（建议 ×0.8），结算文本是归档腔（"已入藏，编号 2098-XXX，谢谢"）。**反差即讽刺**：私人的痛苦被归档成藏品。
- **稀有点缀，非稳定收益**：层二是高方差的情感时刻，不是稳定经济来源。玩家无法"靠刷遗物致富"，但偶遇匹配会有强记忆点。

> 这正是"地球遗物被消费"主题的机制落点：**同一封信，对怀念地球的一代是无价，对收藏地球的三代只是一个编号。**

## 5. 检视系统接口（预留，详见 Task #2）

层二遗物是检视系统的主要对象。本 spec 只预留契约，不展开（检视交互 / 程序 / 联机由 Task #2 设计）：

- 捡起可**举起旋转看细节**：信封收件人名字 / 照片里模糊的脸 / 玩具磨损。
- **检视不改变价值**（避免"必须检视才值钱"的负担）；它改变的是玩家的**认知与情感连接**。
- 数据预留：`relic.targetPersonId`（对应的人）、`relic.inspectDetail`（检视细节贴图 / 文本，可选）。

## 7. 结算公式 & 受影响系统（PATCH）

**结算公式**（原 `MissionRewardCalculator`：`Σ(baseValue × condition × clientPreferenceMultiplier)`）拆为两层求和：

```
层一_i = baseValue × cond × (matchesClass ? materialClassPreferenceMultiplier : 1.0)
层二_j = baseValue × cond × (matchesClient ? relicEmotionalMultiplier : relicMismatchMultiplier)
结算 = Σ层一_i + Σ层二_j
```

| 系统 / 数据 | 改动 |
|---|---|
| `ScavengeItemDefinition` | 加 `tier`(Salvage/Relic)；层一加 `materialClass`；层二加 `targetPersonId` + 可选 `inspectDetail` |
| `OfficeTaskDefinition` | 客户偏好字段从 `favouredCategories` 改为 `favouredMaterialClasses`(1–2)；个人客户加 relic 情感匹配规则 |
| `MissionRewardCalculator` | 实现上面的双层公式 |
| `design/quick-specs/scavenging-item-system-2026-06-16.md` | Rule 5 重写、Item Categories 重组、Tuning 增改（PM 批准本草案后合并）**【D5】** |
